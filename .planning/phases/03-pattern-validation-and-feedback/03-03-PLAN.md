# Plan 03-03: User Feedback And Regression Contracts

<objective>
Surface concise validation warnings/failures in the existing app shell, keep invalid sources out of selection and playback, provide safe empty states, and lock the behavior with regression tests.
</objective>

## must_haves
- D-03: Use structured summaries without exposing raw diagnostics to users.
- D-05: Invalid sources must not be selectable.
- D-06: Show clear warning/failure feedback for rejected sources.
- D-07: Developer diagnostics remain useful while app boot stays resilient.
- D-08: No-valid-source state must be explicit and safe.
- D-13: Feedback copy must be brief and action-oriented.
- D-14: The score area must not become a developer error dump.
- D-15: Preserve sound, keyboard, and button responsiveness.
- D-16: Cover valid and malformed fixture behavior.
- D-17: Cover hidden invalid selector entries and feedback hooks.
- D-18: Preserve Lombard, Fuer Elise, chord, rest, transposition, timing, measure grouping, validation, and unsupported-key coverage.
- D-19: Keep diagnostic code/path assertions where practical.
- D-20: Do not implement default-library management UI.
- D-21: Do not implement remembered MusicXML persistence.
- D-22: Do not implement MusicXML import/file picker/removal.
- D-23: Make rejected-source failures understandable to users.

## truths
- D-03: Visible feedback and developer diagnostics are separate.
- D-05: Selector options are valid-only.
- D-06: Warning/failure status region is the UI mechanism.
- D-07: Partial load failure does not crash the app.
- D-08: Empty state replaces broken playback/rendering.
- D-13: Copy follows UI-SPEC.
- D-14: Score pages remain clean.
- D-15: Sound/keyboard code paths are not redesigned.
- D-16: Tests include real and malformed cases.
- D-17: UI feedback is testable by source contracts and loader behavior.
- D-18: Existing regression tests stay green.
- D-19: Structured diagnostics remain intact.
- D-20: Default library management is deferred.
- D-21: Local MusicXML persistence is deferred.
- D-22: Import/removal UI is deferred.
- D-23: The folded validation UX concern is closed.

<threat_model>
## Security Threat Model

**Scope:** Visible validation notification, selector state, no-valid-source handling, and console diagnostics.

**Threats considered:**
- Raw diagnostic messages may contain developer paths and should not be exposed as user copy.
- Invalid source state could still reach playback if selector or fallback code bypasses the loader gate.
- A no-valid-source state could leave stale Play/Stop handlers or notation highlights active.

**Mitigations required:**
- User-facing copy must come from the UI-SPEC copy contract, not raw diagnostic messages.
- Play path must guard against missing/invalid canonical sequence.
- Pattern change/no-valid-source handling must stop playback and clear notation highlights.
</threat_model>
