<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| User MusicXML to OSMD | User-supplied XML/MXL enters a third-party parser and renderer. |
| OSMD DOM to app interactions | Third-party generated SVG/DOM becomes app hit targets for range and playback. |
| Renderer lifecycle to app state | Long-lived renderer instances can retain DOM listeners or imported score data. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Tampering | Renderer DOM | mitigate | Only insert OSMD output into the controlled notation container and add app classes/data attributes through the facade. |
| T-07-01-02 | Denial of Service | Large scores | mitigate | Preserve static browser-only behavior, track render timing in smoke where feasible, and avoid repeated render loops on resize. |
| T-07-01-03 | Information Disclosure | Local imported scores | mitigate | Keep imported score data local; do not upload or fetch user file content. |
| T-07-01-04 | Spoofing | Fallback renderer | mitigate | Do not silently fall back to the old VexFlow reconstruction for production imports; show a renderer failure state if OSMD cannot render. |
</threat_model>
