## Locked Phase Decisions

Preserve these user decisions exactly as the Phase 5 visual and interaction source of truth:

- Default library shows only complete score-like pieces.
- Imported MusicXML is remembered automatically in browser-local storage.
- Duplicate imports create suffixed entries.
- Imported entries have visible remove actions near the selector/library.
- Strict MusicXML import by default, short toast plus expandable user-facing details on validation failure.
- Imported files must map cleanly to canonical events; no display-only import.
- Display MusicXML as full pages defined by the file, like MuseScore Studio; scale page content within sheet viewport, never reflow into another page.
- Renderer must remain interactive for playback highlights, click events, and possible future editing; static-image-only rendering is forbidden.
- Desktop uses two-page stand; small screens use one-page vertical layout and vertical scroll.
- Range selection uses intentional modified click, preferably Shift+click; selected range uses mint-green accent.
- Start from selected measure first; note/event start only if reliable event clicks exist.
- Existing loop toggle loops selected range if present, otherwise full score.
- Auto-scroll follows playback unless user manually scrolls away, then pauses auto-follow until resumed.

Copy rules:

- Use "score" for complete imported or built-in sheet-like pieces. Use "pattern" only when referring to legacy short pedagogical sources outside the default Phase 5 library.

## Layout Contract

### Library And Import Surface

- Replace the default selector mental model with a score library surface while preserving the existing selectable source path.
- The default visible library must show only complete score-like pieces after browser storage/cache is clear.
- Place `Import MusicXML` near the score selector/library, not in the sound panel.
- Imported scores appear in the same library area as complete built-in scores and must be marked as imported without visual noise.
- Each imported score row or selected imported score detail must expose a visible remove action near the selector/library.
- Remove actions must be icon-capable using Material Icons (`delete` or equivalent), include text or an accessible label, and keep a minimum `44px` target.
- Short pedagogical patterns may remain internally supported but must not dominate the default Phase 5 library surface.

### Sheet Viewport

- Use the existing `.staff-notation`, `#vexflow-notation`, `.score-sheet-view`, `.score-page-grid`, and `.score-page` visual language unless a renderer spike proves a replacement container is required.
- Primary focal point is the sheet viewport/current score page; import/library controls are secondary, and range/auto-follow status is tertiary.
- Display MusicXML as full pages defined by the file. Scale page content within the sheet viewport; never reflow measures or systems into different pages because of viewport width.
- Desktop and wide layouts use a two-page stand with a `32px` gap.
- Small screens use one-page vertical layout with vertical scroll.
- The fixed bottom piano keyboard must never cover the active playback system, validation details, range badge, or import controls. Maintain bottom padding tied to `--piano-bottom-space`.
- Avoid adding cards inside the sheet area. The sheet pages themselves are the framed objects.

### Practice Control Placement

- Keep Play, Loop, tempo, swing, and sustain in the main control area unless implementation proves a dense toolbar is needed.
- Add range status and clear action close to the score surface, above the page viewport.
- Add the auto-follow paused notice and `Resume follow` action near the range status, not inside the sound panel.
- Do not move piano sound controls into the import/practice flow.

## Interaction Contract

### Import

- File picker accepts `.musicxml` and `.xml`.
- Successful import automatically remembers the score in browser-local storage and immediately selects or visibly adds the imported entry.
- Duplicate imports with the same filename/title create a new suffixed entry; never replace silently.
- If automatic persistence fails, the import fails visibly. Do not register a score that will disappear on refresh.
- Importing is strict by default. There is no lenient toggle in Phase 5.
- Failed import shows a short toast plus expandable user-facing details.
- Unsupported MusicXML parts or features must be rejected rather than silently skipped.
- Imported files must map cleanly to canonical events before display/playback; display-only import is forbidden.

### Removal

- Remove applies only to imported local scores.
- Destructive confirmation text must match the Copywriting Contract.
- After removal, the library returns to the nearest available complete score and the score viewport updates immediately.
- Removing an imported score must not alter original files, built-in scores, settings, sound controls, or piano resize state.

### Range Selection

- Range selection uses `Shift+click` on rendered measures as the primary gesture.
- First `Shift+click` sets the range start measure.
- Second `Shift+click` sets the range end measure; if the second measure is earlier, normalize the range so start is lower than end.
- Selected range uses the mint-green accent.
- Plain click remains available for future note/event interactions and must not create a range by itself.
- Start from selected measure is required. Start from selected note/event is allowed only if reliable event clicks exist.
- Provide `Clear range` whenever a range exists.

### Playback And Looping

- Existing loop toggle loops the selected range when present.
- Existing loop toggle loops the full score when no range exists.
- Starting playback with a selected range begins at the selected range start measure.
- Playback highlights must remain interactive SVG/DOM-level highlights, not static image overlays.
- Playback note highlight color stays amber (`#F6A510`) and must remain visually distinct from the mint range selection.
- Stopping playback clears transient playback highlights but keeps the selected range.

### Auto-Follow

- Auto-scroll follows the current playback system/page while playback is active.
- Manual user scroll pauses auto-follow.
- While paused, show `Auto-follow paused` and a `Resume follow` action.
- Auto-follow resumes when the user activates `Resume follow` or restarts playback.
- Auto-follow must not fight the user during manual scroll and must not scroll the fixed bottom keyboard.

## Responsive Contract

| Breakpoint | Contract |
|------------|----------|
| Wide desktop (`> 1200px`) | Main score surface centered; two-page stand; sound panel may collapse from right; import/library controls stay above the sheet viewport. |
| Tablet/narrow desktop (`769px-1200px`) | Main layout stacks as currently defined; two-page stand may scale down but must not reflow pages. |
| Mobile (`<= 768px`) | One-page vertical layout; vertical scroll; controls stack full width; validation details wrap long paths/messages; fixed piano remains bottom-reserved. |

Touch/mobile behavior:

- Because `Shift+click` is not available on touch-only devices, provide an explicit range mode or equivalent modified selection affordance if mobile range selection is included in Phase 5. The selected visual state and loop behavior must match desktop.
- All new interactive controls need at least `44px` target height.
- Long filenames and diagnostic messages must wrap with `overflow-wrap: anywhere`.

---

## Accessibility Contract

- File input, import button, selector/library, remove actions, validation details, range controls, and auto-follow controls must have visible labels or accessible names.
- Expandable import details must use native `<details>`/`<summary>` or equivalent ARIA-expanded behavior.
- Toasts and validation status must use a polite live region; fatal import failures may use assertive only if they block the immediate action.
- `Shift+click` range selection must have a keyboard-accessible alternative if range selection is exposed to keyboard users.
- Focus styles must remain visible and use existing focus treatment or a mint outline only for range-related controls.
- Do not rely on color alone for selected ranges; include boundary marks, range badge text, or both.

---

## Validation And State Contract

Required states:

- Empty imported library with default complete score-like built-ins visible.
- Import in progress.
- Import success.
- Import failure with collapsed details.
- Import failure with expanded details.
- Imported score selected.
- Duplicate imported score selected with suffixed title.
- Imported score removal confirmation.
- Range start pending.
- Range selected.
- Playback active inside full score.
- Playback active inside selected range.
- Auto-follow active.
- Auto-follow paused by manual scroll.
- Storage failure.

Validation display:

- Short toast: one sentence, no stack traces.
- Expandable details: user-facing messages first, structured code/path details second.
- Fatal validation should prevent playback and rendering registration.
- Accepted imports must have passed canonical validation before the score appears as playable.
