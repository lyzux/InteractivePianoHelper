# Plan 01-02: Playback And Notation Consume Canonical Events

<objective>
Wire playback, notation rendering, and highlight coordination to the canonical event sequence so the app plays exactly the syntactically valid notes it displays for built-in pattern previews.
</objective>

## must_haves
- D-01: Visible notation must be syntactically valid music notation.
- D-02: Playback must play the same event sequence that notation displays.
- D-03: Looping must occur after the displayed complete loop unit.
- D-04: Loop units are per-pattern canonical decisions.
- D-07: Musical corrections are allowed when they improve interpretation.
- D-08: Preserve sound generation, piano UI, and the phase boundary.
- D-11: Fold the notation/playback contract todo into execution scope.

## truths
- D-01: Visible notation must be syntactically valid music notation.
- D-02: Playback must play the same canonical event sequence that notation displays.
- D-03: Looping must happen after the displayed complete measure, phrase, or pattern unit.
- D-04: Short-loop behavior must be decided per pattern through canonical metadata/defaults.
- D-07: Musical corrections are allowed when current pattern data seems awkward, incomplete, or inconsistent.
- D-08: Corrections must not redesign sound generation, piano UI, full score display, or MusicXML import.
- D-11: The folded `Harden notation playback contract` todo is in scope for shared resolver and playback/notation agreement work.

<threat_model>
## Security Threat Model

**Scope:** Browser-side playback/notation integration for local built-in patterns.

**Threats considered:**
- Scheduling invalid notes could create broken user-visible behavior, but does not introduce a backend security surface.
- Pattern modules are still executable local code; this phase must not add arbitrary user-imported JavaScript execution.
- DOM updates for notation must not render unsanitized external content; Phase 1 uses local pattern names and generated SVG only.

**Mitigations required:**
- Keep MusicXML/user import out of Phase 1.
- Do not add network calls or backend endpoints.
- On unsupported canonical sequences, do not start playback.
- Preserve `Player.stop()` cleanup to avoid stuck highlights or runaway timers.
</threat_model>

<title>Schedule playback from canonical events</title>
<read_first>

- `js/canonicalPatternResolver.js`
- `js/piano.js`
- `js/audioEngine.js`
- `.planning/phases/01-canonical-pattern-event-pipeline/01-RESEARCH.md`

<action>
Refactor `js/player.js` so `Player` schedules from canonical event objects rather than resolving `leftHandNotes`, `rightHandNotes`, and `pattern.timing` internally. Remove the private duplicated playback transposition helpers: `_SHARP_P`, `_FLAT_P`, `_ENARH_P`, `_KEY_ST_P`, `_FLAT_KEYS_P`, `_toMidiP`, `_transposeP`, and `_resolveNotesP`.

Preserve `SCHEDULE_AHEAD`, `POLL_INTERVAL`, `_noteDurationSec`, swing behavior for `0.5` beat durations, sustain handling, piano key highlight/unhighlight timers, `stop()` cleanup, and `isCurrentlyPlaying()`.

For each canonical event, schedule left and right hand payloads from `event.hands.left` and `event.hands.right`. Skip rests. For chords, pass the note array through the existing `AudioEngine.playNote` and `Piano.highlightKey` paths, which already support arrays. Advance `beatPosition` by `event.durationBeats`. Loop after `events.length` and reset `beatPosition` to `0` at the canonical loop boundary. Fire `onNoteHighlight(event.id, event)` instead of a raw modulo note index.
</action>
<verify>
- Run `npm test`.
- Run `rg "_SHARP_P|_resolveNotesP|leftHandNotes|rightHandNotes|currentTiming" js/player.js`; removed state/helpers should not remain as active scheduling inputs.
- Manual smoke: play Lombard at default tempo and confirm playback loops after the displayed complete unit.
</verify>
<acceptance_criteria>
- `js/player.js` does not contain `_resolveNotesP`.
- `js/player.js` schedules from `event.durationBeats`.
- `Player.onNoteHighlight` receives a canonical event ID.
- `Player.stop()` still clears scheduler timer, visual timeouts, and piano highlights.
</acceptance_criteria>
</task>
