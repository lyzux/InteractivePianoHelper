# Plan 02-01: Authored Score Controls And Loop Playback

<objective>
Remove key-changing from the active UI path, resolve score content in its authored key, and add off-by-default loop playback so the controls match the sheet-first Phase 02 direction before the renderer is repaged.
</objective>

## must_haves
- D-01: The UI must resolve every selected item as sheet-first score content, not as a compact pattern-first preview.
- D-02: Existing short built-in patterns must still render and play through the same sheet-first path.
- D-03: Display mode separation must be explicit in code/metadata without adding a prominent user-facing compact/full switch.
- D-08: Add a loop control for score playback.
- D-09: Looping must be disabled by default.
- D-10: Loop mode loops the complete current canonical score source only; selected-measure practice looping remains future work.
- D-11: Remove the key change feature from the active product path.
- D-12: Native-key pieces such as Fur Elise must display in their authored/original key instead of exposing unsupported key choices.
- D-13: Future MusicXML content must be loaded/displayed as written; key editing and transposition are out of scope.

## truths
- D-01: Full score preview is the default product direction.
- D-02: Short built-in patterns remain supported as score content.
- D-03: The old compact/full wording is implemented as internal display metadata, not a user toggle.
- D-08: The loop control is a simple binary score playback option.
- D-09: Initial loop state is off/unchecked.
- D-10: Looping applies to the complete canonical sequence only.
- D-11: The key selector and key-change handlers are removed from active UI.
- D-12: Authored-key resolution prevents unsupported native-key selections.
- D-13: The app should not edit, transpose, or reinterpret content in Phase 02.

<threat_model>
## Security Threat Model

**Scope:** Browser-side controls, local pattern resolution, and playback scheduler state.

**Threats considered:**
- Removing key UI must not introduce arbitrary user-provided code or file parsing.
- Loop playback must not create runaway timers after Stop, pattern change, or page unload.
- Stored settings may contain old `key` data from previous versions; Phase 02 must ignore it without crashing.

**Mitigations required:**
- Keep all changes in static browser modules.
- Preserve `Player.stop()` cleanup for scheduler timer, visual timeouts, and piano highlights.
- Treat old saved `key` settings as inert legacy data; do not use them for active score resolution.
</threat_model>
